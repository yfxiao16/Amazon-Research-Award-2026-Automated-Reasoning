\section{Additional information}

\textbf{1. Application domain and analysis techniques.} Compositional design of distributed systems, multi-robot systems, and hardware, using \gls{ag} contracts, mixed-integer linear programming (Gurobi), \gls{ltl} model checking (nuXmv), \gls{smt} reasoning, GR(1) synthesis (slugs), and hardware model checking (SymbiYosys, Jasper). It covers sound neurosymbolic reasoning, LLM--solver interfaces, auto-formalization of contracts, and verification of distributed systems, robots, and hardware.

\textbf{2. Current applications.} \chase has been used for requirement formalization and validation of cyber-physical systems~\cite{nuzzo2018chase}, contract-based architecture exploration~\cite{xiao2024contrarc,xiao2026smcp}, consistency and availability analysis of distributed systems with Lockheed Martin~\cite{xiao2026memocode}, and multi-robot controller synthesis~\cite{xiao2026acies}. Our RTL flow is being applied to OpenTitan and HierSVA designs.

\textbf{3. Potential applications to Amazon.} (i) Distributed cloud services, where end-to-end latency, availability, and consistency budgets can be decomposed into per-component timing contracts with worst-case bounds~\cite{xiao2026memocode}, complementing protocol-level models in TLA+ or P. (ii) Amazon Robotics fleets, where missions can be decomposed hierarchically into contracts for small groups of robots, and learned \gls{vla} policies can be guarded at run time by contract monitors and post-trained with contract-based rewards. (iii) AWS processors and accelerators, where end-to-end properties of interconnects and coherence controllers too large for direct model checking can be decomposed into module-level SVA contracts that are reused when a block is resized.

\textbf{4--5. Prior Amazon Research Awards.} No\yifeng{, and no Amazon funding or AWS credits in the past three years}.

\textbf{6. Assumptions and soundness.} A certified result is sound when (i) the back ends return correct verdicts, (ii) the translation into each back end preserves the semantics of the contracts, (iii) the embeddings between formalisms are conservative approximations, (iv) mutual assumptions between hardware modules are safety properties, and (v) the top-level specification, which agents cannot edit, is correct. Every contract is checked for consistency and compatibility, so that no refinement holds trivially. Learned components are covered only through verified safety filters. Bounded results never count as proofs, and LLM outputs are never trusted.
