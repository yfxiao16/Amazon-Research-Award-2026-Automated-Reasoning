\section{Methods}

\sysname represents a design as a directed acyclic graph of contracts, where each node is a component with a contract over its ports. At an internal node, an agent proposes one contract for each subcomponent. The proposal is accepted only if the component contracts are consistent, bounded checks on the actual components find no counterexample, and their composition refines the parent contract. Each subcomponent is then discharged by a back end or further decomposed; a node that cannot satisfy its contract returns a witness to its parent, which revises the decomposition while certified subtrees are kept. The leaves depend on the domain: a hardware module that a model checker proves directly, a task that one LLM agent completes or a piece of deterministic code, or a robot controller certified by, e.g., a control barrier function or Hamilton-Jacobi reachability.

\thrust{Thrust 1: Decomposition of Temporal Contracts.} GR(1) synthesis~\cite{bloem2012gr1} is the common back end of our robotic and agentic flows.
\rqbox{RQ 1.}{Given a system contract in the GR(1) fragment and an architecture, devise (a) conditions under which a decomposition into realizable component contracts exists, (b) sound approximations of the contract quotient within GR(1), and (c) methods to reason about components that depend on each other circularly.}
\emph{Task 1. Decidable classes and quotient approximations.} We will identify classes of architectures and contracts for which the existence of a decomposition is decidable, starting from pipeline architectures, for which distributed synthesis is decidable~\cite{pnueli1990distributed}, and use the agent as a search heuristic outside these classes. We will develop GR(1) approximations that strengthen the guarantees of the exact quotient: they can be solved directly by a synthesis tool, and any controller synthesized for them is correct for the composition. \emph{Task 2. Circular reasoning and learned constraints.} We will restrict the guarantees used as assumptions to safety properties, adopt a circular \gls{ag} rule with an inductive side condition~\cite{mcmillan1999circular,namjoshi2000completeness}, and characterize the decompositions it admits. As learned clauses prune the search of a SAT solver, we will generalize the unrealizable core of a failed decomposition, via subgraph isomorphism~\cite{xiao2024contrarc}, into a constraint that excludes every candidate assigning an isomorphic component the same terms.

\thrust{Thrust 2: Decomposition of Agentic Tasks.} Whether one agent or several perform better depends on the task~\cite{kim2025scaling}, and delegation is where rules are lost.
\rqbox{RQ 2.}{Given a task contract over the actions of an agentic workflow, devise methods to (a) decide whether and how the task is delegated to roles, (b) generate role contracts whose composition refines the task contract, and (c) optimize the decomposition jointly with the cost of executing the roles.}
\emph{Task 3. Contract-based delegation.} A parent agent passes to each role a task, a context, and contracts in \gls{ltlf}~\cite{degiacomo2013ltlf}, inherited or generated, and the engine checks that their composition refines the parent contract. A role may need weaker assumptions, stronger guarantees, and conditions on its siblings, such as sending a confirmation only after a payment; the quotient of the parent contract by the contracts of the siblings gives the weakest admissible contract. A compacted context is accepted only if its contracts refine those of the full context. Vacuity~\cite{maoz2020vacuity} and well-separation~\cite{maoz2016wellsep} checks reject faulty contracts, and the choice between one agent and several is cast as contract-based architecture exploration~\cite{xiao2024contrarc,xiao2026smcp}. \emph{Task 4. Joint optimization with inference cost.} The states reachable in a role contract determine which tools the role may call next. We will use them to partition the key-value cache of the model into modules aligned with contract states~\cite{gim2024promptcache,yao2025cacheblend} and to prefetch modules for reachable states, so that dynamic tool lists do not invalidate cached prefixes, and include this cost in Task~3. Enforcement of the contracts at run time reduces to monitoring~\cite{xiao2026symbolic} and is outside the scope of this project.

\thrust{Thrust 3: Formal Feedback, Repair, and Reuse.}
\rqbox{RQ 3.}{Given a failed decomposition step, devise methods to (a) return feedback that localizes the failure, (b) repair the decomposition with as few agent calls as possible, and (c) reuse certified components across designs.}
\emph{Task 5. Layered feedback.} The engine separates a formalism-independent contract algebra, checks reduced to validity or satisfiability, and formalism-specific analyses such as unrealizable cores; every failed check returns a counterexample or a minimal core. A \gls{mcp} server and an agent skill expose all operations to agents; no LLM is part of the engine. \emph{Task 6. Repair, reuse, and coverage.} Refinement failures are first repaired with the quotient, before any agent call. Certified components are reused after their assumptions are rechecked, and contract coverage is measured by fault injection.

\thrust{Evaluation and preliminary results.} In hardware, component contracts are \glspl{sva} with ghost-state models, verified with Cadence Jasper and the open-source SymbiYosys. Our prototype certified an end-to-end in-order delivery property of a HierSVA asynchronous link with 25 Jasper runs and about 16,000 LLM input tokens, which flat Jasper did not decide in the same time; the decomposition found at FIFO depth 8 certified depths 16 to 512 with no further LLM calls, and an agent without the protocol used 24 times as many tokens without completing the proof. In multi-robot control, ACIES~\cite{xiao2026acies} decomposes mission requirements into GR(1) contracts and synthesizes controllers; in a three-level decomposition with 42 nodes, the contract library closed 26 of the 39 leaves. For agentic software, we will add delegation, compaction, and cache-aware tool exposure one at a time to a single-agent executor on long-horizon tasks from AppWorld~\cite{trivedi2024appworld}, against summarization-based compaction.
