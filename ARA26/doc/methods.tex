\section{Methods}

\sysname pursues three research thrusts. The first extends contract theory to the layers on which agents now operate; the second develops a single iterative decomposition method that applies to all of them; the third turns the outcome of each decomposition step into feedback, repairs, and a library of certified components that grows from one design to the next.

\thrust{Thrust 1: Contract Theory for Hardware, Robotic, and Agentic Layers.} Contract-based design has been developed mostly for cyber-physical components with fixed interfaces~\cite{benveniste2018contracts}. We will extend the modeling to the three layers targeted by this project. For hardware, a contract relates the ports of a register-transfer-level module over clock cycles and may refer to ghost state, such as the content of a buffer, which must itself be verified on the design. For robots, a contract couples a discrete mission layer, expressed in GR(1)~\cite{bloem2012gr1}, with continuous-time controllers whose guarantees come from control barrier functions~\cite{ames2019cbf} or Hamilton-Jacobi reachability. Learned policies, such as vision-language-action models~\cite{kim2024openvla}, cannot be verified offline; their contracts are enforced at run time by safety filters and monitors, which report violated assumptions back to the decomposition. For agents, a contract in \gls{ltlf}~\cite{degiacomo2013ltlf} constrains the sequence of tool calls of a role, and its assumptions describe what the role may expect from the context it receives and from its sibling roles. On top of these models, we will study the algebraic questions that decomposition raises. The existence of a decomposition into realizable components is undecidable for general architectures~\cite{pnueli1990distributed}; we will identify classes of architectures and contracts for which it is decidable, starting from pipelines. The quotient of two GR(1) contracts in general leaves the fragment; we will develop approximations within GR(1) that strengthen the guarantees of the exact quotient, so that any controller synthesized for them is correct for the composition. Finally, circular dependencies arise naturally in pipelines, handshake protocols, and agents that wait on each other; we will adopt a circular \gls{ag} rule restricted to safety guarantees with an inductive side condition~\cite{mcmillan1999circular,namjoshi2000completeness}, and characterize the decompositions it admits.

\thrust{Thrust 2: Iterative Contract-Based Decomposition.} \sysname represents a design as a directed acyclic graph of contracts, built recursively. At an internal node, an agent proposes one contract for each subcomponent. The proposal is accepted only if the component contracts are consistent, bounded checks on the actual components find no counterexample, and their composition refines the parent contract. Each subcomponent is then discharged by a back end or decomposed in turn, and a node that cannot satisfy its contract returns a witness to its parent, which revises the decomposition while certified subtrees are kept. The same procedure applies to all three layers, and only the leaves change: a hardware module that a model checker proves directly, a robot controller certified by a synthesis or reachability tool or a learned policy guarded at run time, or a task that one LLM agent completes within its context or a piece of deterministic code. In agentic workflows, a decomposition step corresponds to delegation: a parent agent passes to each role a task, a context, and a set of contracts, inherited or generated, and the quotient of the parent contract by the contracts of the sibling roles gives the weakest contract a role must satisfy. A compacted context is accepted only if its contracts refine those of the full context, and the choice between one agent and several~\cite{kim2025scaling} is cast as contract-based architecture exploration~\cite{xiao2024contrarc,xiao2026smcp}. Because the contracts of a role determine which tools it may call next, the decomposition can be optimized jointly with the cost of executing the roles, by partitioning the key-value cache of the model into modules aligned with contract states~\cite{gim2024promptcache,yao2025cacheblend} and prefetching modules for reachable states.

\thrust{Thrust 3: Formal Feedback, Repair, and Reuse.} The value of the decomposition engine for an agent lies in what it returns when a step fails. The engine separates a formalism-independent contract algebra, checks reduced to validity or satisfiability, and formalism-specific analyses such as unrealizable cores, vacuity~\cite{maoz2020vacuity}, and well-separation~\cite{maoz2016wellsep}; every failed check returns a counterexample or a minimal core that points to the responsible terms. A \gls{mcp} server and an agent skill expose these operations to agents, while no LLM is part of the engine. Refinement failures are first repaired with the quotient, before any agent call. As learned clauses prune the search of a SAT solver, the core of a failed decomposition is generalized via subgraph isomorphism~\cite{xiao2024contrarc} into a constraint that excludes every candidate assigning an isomorphic component the same terms. Certified contracts are stored together with their components, so that the contract library grows with each design and a component can be reused elsewhere after its assumptions are rechecked; the coverage of the library is measured by injecting faults into the components.

\thrust{Evaluation and preliminary results.} In hardware, component contracts are \glspl{sva} with ghost-state models, verified with Cadence Jasper and the open-source SymbiYosys. Our prototype certified an end-to-end in-order delivery property of a HierSVA asynchronous link with 25 Jasper runs and about 16,000 LLM input tokens, which flat Jasper did not decide in the same time; the decomposition found at FIFO depth 8 certified depths 16 to 512 with no further LLM calls, and an agent without the protocol used 24 times as many tokens without completing the proof. In multi-robot control, ACIES~\cite{xiao2026acies} decomposes mission requirements into GR(1) contracts, synthesizes controllers, and executes them under control barrier functions with runtime monitors; in a three-level decomposition with 42 nodes, the contract library closed 26 of the 39 leaves. For agentic software, we will add delegation, compaction, and cache-aware tool exposure one at a time to a single-agent executor on long-horizon tasks from AppWorld~\cite{trivedi2024appworld}, against summarization-based compaction.
