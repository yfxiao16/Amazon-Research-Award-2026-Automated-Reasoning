\section{Methods}

\sysname represents a design as a directed acyclic graph of contracts, where each node is a component with a contract over its ports. At an internal node, an agent proposes one contract for each subcomponent. The proposal is accepted only if the component contracts are consistent, bounded checks on the actual components find no counterexample, and their composition refines the parent contract. Each subcomponent is then discharged by a back end or, if this does not terminate within a budget, further decomposed. When a node cannot satisfy its contract, it returns a witness to its parent, which revises the decomposition while certified subtrees are preserved. The research is organized in three thrusts.

\thrust{Thrust 1: Decomposition of temporal contracts.} We will study the decomposition of a system contract in the GR(1) fragment~\cite{bloem2012gr1} into realizable component contracts over a given architecture. First, we will identify classes of architectures and contracts for which the existence of a decomposition is decidable, starting from pipeline architectures, for which distributed synthesis is decidable~\cite{pnueli1990distributed}, and use the agent as a search heuristic outside these classes. Second, we will develop sound GR(1) approximations of the quotient. An approximation that strengthens the guarantees of the exact quotient yields a contract that a synthesis tool can solve directly, and any controller synthesized for it is correct for the composition. When the approximation is unrealizable, its unrealizable core indicates which terms to weaken in the next approximation. Third, we will handle circular dependencies by restricting the guarantees that can be used as assumptions to safety properties, adopting a circular \gls{ag} rule with an inductive side condition~\cite{mcmillan1999circular,namjoshi2000completeness}, and characterizing the class of decompositions this rule admits. Fourth, as learned clauses prune the search of a SAT solver, we will generalize the unrealizable core of a failed decomposition, via subgraph isomorphism~\cite{xiao2024contrarc}, into a constraint that excludes every candidate assigning an isomorphic component the same terms.

\thrust{Thrust 2: Temporal obligations under delegation and compaction.} We will extract the rules that an agent must follow throughout a task from its instructions and context into a library of contracts in \gls{ltlf}~\cite{degiacomo2013ltlf}. Delegation then becomes a decomposition step: when an agent hands a subtask to a sub-agent and retains the rest, the sub-agent receives the quotient of the parent contract by the contract of the retained part, which is the weakest contract under which the overall obligations still hold. Context compaction becomes an abstraction step, which is sound when the compacted contract library refines the contract induced by the full context; the engine checks this condition before the context is discarded. The research questions include the extraction of contracts from natural-language context, where consistency, vacuity~\cite{maoz2020vacuity}, and well-separation~\cite{maoz2016wellsep} checks reject faulty formalizations; the efficient computation of quotients over finite traces; and the choice between one agent and several. We will cast this choice as a contract-based architecture exploration problem~\cite{xiao2024contrarc,xiao2026smcp}, in which a split is admissible only if every role contract is realizable or monitorable and the interfaces between roles are small. Once the contracts are available, their enforcement at run time reduces to monitoring~\cite{xiao2026symbolic} and is outside the scope of this project.

\thrust{Thrust 3: Formal feedback, repair, and reuse.} The contract engine will be organized in three layers: a contract algebra independent of the formalism; contract-level checks, each reduced to the validity or satisfiability of a formula; and analyses specific to a formalism, such as realizability and unrealizable cores for GR(1). Every failed check returns a counterexample trace or a minimal core identifying the terms responsible for the failure. A \gls{mcp} server and an agent skill expose all the operations to LLM agents, while no LLM is part of the engine. A symbolic controller enforces the verification protocol: a property is claimed only after the back-end result has been read and the vacuity checks have passed, and bounded or timed-out runs are counted as undetermined. Refinement failures are first repaired mechanically using the quotient, and the agent is invoked only when this repair does not succeed. Certificates are stored with the component and the mapping of its ports, so that a certified component can be reused in another design after its assumptions are rechecked. Finally, we will measure how much of an implementation the certified contracts constrain by injecting faults into the components and checking which faults the contracts detect.

\thrust{Applications and preliminary results.} We will evaluate \sysname in three domains. In hardware verification, component contracts are \glspl{sva} with ghost-state models, verified with Cadence Jasper and, in this project, the open-source SymbiYosys. Our prototype certified an end-to-end in-order delivery property of an asynchronous link from the HierSVA benchmark with 25 Jasper runs and about 16,000 LLM input tokens, which flat Jasper did not decide in the same time. The decomposition found at FIFO depth 8 certified depths 16 to 512 with no further LLM calls, and every injected fault observable at the property was located in the faulty module. An agent given the same tools without the verification protocol did not complete the proof and consumed about 24 times as many tokens. In multi-robot control, ACIES~\cite{xiao2026acies} decomposes mission requirements into GR(1) contracts and synthesizes controllers; in a three-level decomposition with 42 nodes, the contract library closed 26 of the 39 leaves. In multi-agent software, we will evaluate delegation and compaction on long-horizon tasks from AppWorld~\cite{trivedi2024appworld}, using the failure taxonomy of~\cite{cemri2025mast}.
