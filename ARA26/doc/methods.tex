\section{Methods}

The core of \sysname is a neurosymbolic loop: LLM agents propose decompositions (Thrust~2), a contract engine certifies them on the theory of Thrust~1, and its verdicts return to the agents, in context and as rewards for post-training (Thrust~3). Hardware is the main testbed, \yifeng{followed by robots and distributed systems.}

\thrust{Thrust 1: Contract Theory for Decomposition.} Hardware contracts relate the ports of register-transfer-level modules over clock cycles and may refer to ghost state verified on the design. Robot contracts couple a GR(1) mission layer~\cite{bloem2012gr1} with controllers certified by control barrier functions~\cite{ames2019cbf} or reachability; learned policies, such as vision-language-action models~\cite{kim2024openvla}, are guarded at run time by safety filters and monitors that report violated assumptions to the decomposition. \yifeng{In distributed systems, timing contracts relate the logical order of events to execution and communication latencies and bound the inconsistency and unavailability of each component~\cite{xiao2026memocode}.} The existence of a decomposition into realizable components is undecidable in general~\cite{pnueli1990distributed}; we will identify decidable classes, starting from pipelines. Since the quotient of two GR(1) contracts in general leaves the fragment, we will develop approximations within GR(1) that strengthen its guarantees, so that any controller synthesized for them is correct for the composition. For circular dependencies in pipelines, handshakes, and \yifeng{nodes} that wait on each other, we will adopt a circular \gls{ag} rule restricted to safety guarantees with an inductive side condition~\cite{mcmillan1999circular,namjoshi2000completeness}.

\thrust{Thrust 2: Agentic Decomposition Search.} \sysname represents a design as a directed acyclic graph of contracts, built recursively by LLM agents. At an internal node, an agent receives the parent contract, the interfaces of the subcomponents, and certified decompositions of similar components retrieved from the library, and proposes one contract for each subcomponent, formalizing natural-language requirements where needed. The proposal is accepted only if the component contracts are consistent and non-vacuous, bounded checks on the actual components find no counterexample, and their composition refines the parent contract. Each subcomponent is then discharged by a back end or handed to a new agent whose context contains only its own contract and therefore does not grow with the design; a node that cannot satisfy its contract returns a witness to its parent, which revises the decomposition while certified subtrees are kept. Alternative decompositions are explored by a tree search in which the LLM acts as the policy and the engine prunes candidates. Only the leaves change across domains: a hardware module proved by a model checker, a robot controller certified by a synthesis or reachability tool, a learned policy guarded at run time, \yifeng{or a networked component whose timing contract is checked by mixed-integer linear programming. Sibling agents share the parent contract, library entries, and engine operations, so \sysname partitions the key-value cache of these prompts into modules aligned with contract states~\cite{gim2024promptcache,yao2025cacheblend}, reused across agents and prefetched for the states the contract automata can reach next, to reduce the inference cost.}

\thrust{Thrust 3: Learning from Formal Feedback.} The engine separates a formalism-independent contract algebra, checks reduced to validity or satisfiability, and formalism-specific analyses such as unrealizable cores, vacuity~\cite{maoz2020vacuity}, and well-separation~\cite{maoz2016wellsep}; every failed check returns a counterexample or a minimal core that points to the responsible terms. A \gls{mcp} server and an agent skill expose these operations to agents, while no LLM is part of the engine. Refinement failures are first repaired with the quotient, before any agent call; otherwise, the counterexample is returned to the agent in context as a trace over the responsible contract terms. As learned clauses prune the search of a SAT solver, the core of a failed decomposition is generalized via subgraph isomorphism~\cite{xiao2024contrarc} into a constraint that excludes every candidate assigning an isomorphic component the same terms. Certified contracts are stored with their components in a library that grows with each design, and whose coverage is measured by injecting faults. Beyond in-context feedback, certified decompositions, together with the module hierarchies of existing designs as weak supervision, are used for supervised fine-tuning of an open-weight proposer; reinforcement learning then uses the checks of the engine as verifiable rewards, graded by the consistency, refinement, and realizability of each component contract, so that partially correct decompositions still provide signal. Since every proposal is still checked by the engine, soundness does not depend on the proposer.

\thrust{Evaluation and preliminary results.} \textcolor{blue}{Our prior work combines diverse candidate generation, solver-based screening, and auditable agent execution to improve auto-formalization reliability~\cite{ni2026agentified,ni2026draftprune}\footnote{\url{https://github.com/zyni2001/draft-and-prune}}. These methods underpin contract generation, checking, and feedback-guided revision in \sysname.} In hardware, component contracts are \glspl{sva} with ghost-state models, discharged by hardware model checkers. Our prototype certified an end-to-end in-order delivery property of a HierSVA asynchronous link with 25 model-checking runs and about 16,000 LLM input tokens, while direct model checking of the end-to-end property did not finish within a considerably longer time limit; the decomposition found at FIFO depth 8 certified depths 16 to 512 with no further LLM calls, and an agent without the protocol used 24 times as many tokens without completing the proof. In multi-robot control, ACIES~\cite{xiao2026acies} decomposes mission requirements into GR(1) contracts, synthesizes controllers, and executes them under control barrier functions with runtime monitors; in a three-level decomposition with 42 nodes, the contract library closed 26 of the 39 leaves. \yifeng{In distributed systems, our timing contracts~\cite{xiao2026memocode} checked and repaired consistency and availability requirements of a braking system and a drone federation.} We will compare frontier models with and without formal feedback and retrieval against the post-trained proposer, measuring the requirements certified beyond direct verification or synthesis, the acceptance rate, and solver runs and tokens per certificate.
